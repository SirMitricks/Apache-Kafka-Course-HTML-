Урок 1. Что такое Kafka

Цель: объяснить своими словами, что такое событие, топик, брокер, продюсер и консьюмер, и назвать задачи, для которых берут Kafka.

Теория

Apache Kafka — распределённая платформа потоковой обработки событий (распределённая — работающая сразу на нескольких серверах; потоковая обработка — работа с данными по мере их появления, а не пачкой раз в сутки). По определению официального введения, она объединяет три возможности: публиковать и читать потоки событий, надёжно хранить их столько, сколько нужно, и обрабатывать их по мере поступления или позже.

Событие фиксирует факт «что-то произошло»: у него есть ключ (признак, по которому события группируются, например имя клиента), значение (содержание события), время и необязательные заголовки (служебные пометки, например источник события). Пример: ключ «Alice», значение «Перевела 200 $ Bob», время 25.06.2020 14:06.

Простая аналогия: Kafka — это не почтовый ящик, из которого письмо исчезает после прочтения, а журнал на полке. Записи дописываются в конец, их можно перечитывать сколько угодно раз, а удаляются они только по истечении срока хранения.

Понятие Что это Аналогия
Событие (record, message) Одна запись: ключ, значение, время Строка в журнале
Топик (topic) Именованный поток событий Папка с журналом, например payments
Партиция (partition) Упорядоченная часть топика на одном брокере Отдельная тетрадь внутри папки
Брокер (broker) Сервер Kafka, хранящий партиции Шкаф, где лежат тетради
Продюсер (producer) Приложение, пишущее события Автор записей
Консьюмер (consumer) Приложение, читающее события Читатель со своей закладкой
Offset Номер события внутри партиции Номер строки

Схема архитектуры (продюсеры пишут в партиции топика, группы консьюмеров читают их независимо) описана текстом выше.

Продюсеры (приложения, которые пишут события) отправляют события в партиции топика, а хранят партиции брокеры (серверы Kafka); консьюмеры (приложения, которые читают события) объединяются в группы: внутри группы каждую партицию читает один консьюмер, а разные группы читают одни и те же события независимо.

Три свойства, которые отличают Kafka от обычной очереди (из неё сообщение исчезает после прочтения):

  1. Продюсеры и консьюмеры не знают друг о друге и не ждут друг друга.
  2. События не удаляются после чтения: их можно прочитать повторно и разными приложениями.
  3. Порядок гарантируется внутри одной партиции, а события с одним ключом попадают в одну партицию.

Где применяют: платежи и банковские операции в реальном времени, отслеживание транспорта, данные с датчиков IoT (Internet of Things, «интернет вещей»: умные устройства, присылающие данные), обработка заказов и действий пользователей, обмен данными между отделами компании, основа для микросервисов (небольших независимых программ, из которых собрана большая система).

Пять программных интерфейсов Kafka (API — наборов функций, через которые программа обращается к Kafka) (мы пройдём их по порядку): Admin API, Producer API, Consumer API, Kafka Streams и Kafka Connect.

Практика (без установки)

Смоделируйте интернет-магазин на бумаге или в таблице.

  1. Выпишите 5 видов событий: например, заказ создан, заказ оплачен, товар отгружен.
  2. Для каждого придумайте имя топика, ключ и значение (какие поля).
  3. Решите, по какому ключу разумно делить события на партиции, чтобы все события одного заказа шли по порядку. Подсказка: ключ — номер заказа.
  4. Назовите по два приложения-продюсера и консьюмера для каждого топика.

Контрольные вопросы

  • Чем топик отличается от партиции?
  • Почему Kafka не удаляет событие после того, как его прочитали?
  • Что гарантирует Kafka про порядок событий и в каких пределах?
  • Почему продюсеру не нужно ждать консьюмера?
