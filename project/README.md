# Итоговый проект (Node.js)

Цель: собрать маленькую систему «интернет-магазин» на кластере из трёх брокеров, используя всё изученное. Все клиенты в этом проекте написаны на Node.js.

### Состав системы

1. **Инфраструктура.** Кластер из Docker Compose (урок 6, практика Б) с реестром схем. Топики: `orders` (события заказов, 3 партиции, репликация 3, `min.insync.replicas=2`), `order-status` и `status-counts` (сжимаемый).
2. **Сервис «магазин» (`shop.js`).** Продюсер с `acks=all` и `enable.idempotence`, ключ — номер заказа, значение — событие в Avro через реестр (урок 8). Публикует также смены статусов в `order-status`.
3. **Сервис «биллинг» (`billing.js`).** Консьюмер группы `billing` с ручным коммитом после обработки (урок 7). Должен переживать перезапуск без потери событий; обработка должна быть безопасна при повторе (урок 9).
4. **Сервис «аналитика» (`analytics.js`).** Другая группа на том же топике; читает независимо от «биллинга» и считает выручку (уроки 3–4).
5. **Счётчик статусов.** `status_count.js` из урока 12.
6. **Интеграция.** Выгрузка топика `orders` в файл через Kafka Connect (урок 11).

### Этапы

1. Поднять кластер и реестр, создать топики, зафиксировать вывод `kafka-topics.sh --describe`.
2. Написать `shop.js` и схему `order_v1.avsc`; убедиться, что события читаются `avro_consumer.js`.
3. Написать `billing.js` и `analytics.js`; доказать, что группы независимы (`kafka-consumer-groups.sh --describe`).
4. Запустить `status_count.js` и проверить счётчики.
5. Настроить Connect-выгрузку и проверить файл.
6. **Отказ брокера.** Пока `shop.js` пишет события, остановить один брокер (`docker stop kafka-2`). Проверить: запись не прервалась, события не потеряны и не задублированы. Запустить брокер обратно, дождаться полной синхронизации реплик (ISR).
7. **Мониторинг.** Снять задержку (lag) групп до и после остановки «биллинга» на минуту (урок 13).

### Требования к сдаче

- Каталог с кодом, `package.json` и `docker-compose.yml`.
- Короткий отчёт: схема системы, выводы команд по этапам 1, 3, 4, 6, 7.
- Ответы на вопросы: что гарантирует ваша доставка («не менее одного раза», «ровно один раз» и почему)? Что будет при падении двух брокеров из трёх? Где в вашем коде может возникнуть дубликат?

### Критерии оценки

Полнота (все компоненты работают), надёжность (переживает отказ брокера и перезапуск консьюмера), понимание (ответы на вопросы обоснованы знаниями из уроков), аккуратность (закрытие соединений, обработка ошибок, понятные сообщения в логе).

Подсказка: большую часть кода можно взять из уроков 7, 8 и 12 — новым будут только склейка сервисов, обработка ошибок и эксперимент с отказом брокера.
