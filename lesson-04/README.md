# Урок 4. Продюсер и консьюмер из консоли

**Цель:** записывать события с ключами, читать их с разных позиций и наблюдать, как ключ определяет партицию.

### Теория

Продюсер выбирает партицию для каждого события по такому правилу: если ключ задан, партиция вычисляется из хеша ключа (числа, которое по фиксированному правилу вычисляется из ключа), поэтому события с одним ключом всегда попадают в одну партицию; если ключа нет, продюсер распределяет события по партициям сам. Консьюмер читает партицию строго по возрастанию offset и запоминает, до какого места дошёл.

На этом уроке мы используем консольные утилиты (программы, которые запускаются из командной строки) из дистрибутива (скачанного архива Kafka): они устроены просто и хорошо показывают, что происходит.

**Важно про имена флагов.** Начиная с Kafka 4.2 ([KIP-1147](https://kafka.apache.org/42/getting-started/upgrade/); KIP — номерное предложение по улучшению Kafka) у консольных утилит изменились имена: `--property` заменён на `--reader-property` у продюсера и на `--formatter-property` у консьюмера, а `--producer-property` и `--consumer-property` — на `--command-property`. Старые имена пока работают, но выводят предупреждение об устаревании и будут удалены в Kafka 5.0. В методичке везде используются новые имена.

### Практика

Понадобятся два терминала, топик `orders` с 3 партициями из урока 3 (если вы увеличивали его до 6, это тоже подойдёт).

**Шаг 1. Запишите события без ключа**

```bash
bin/kafka-console-producer.sh --topic orders --bootstrap-server localhost:9092
> заказ 1 создан
> заказ 2 создан
> заказ 3 создан
```

Завершите ввод через `Ctrl-C`.

**Шаг 2. Прочитайте всё с начала**

```bash
bin/kafka-console-consumer.sh --topic orders --from-beginning --bootstrap-server localhost:9092
```

Обратите внимание на порядок: между партициями он может отличаться от порядка записи. Остановите консьюмер через `Ctrl-C`.

**Шаг 3. Запишите события с ключом**

Утилите нужно сказать, что строка состоит из ключа и значения, разделённых символом:

```bash
bin/kafka-console-producer.sh --topic orders --bootstrap-server localhost:9092 \
  --reader-property parse.key=true --reader-property key.separator=:
> 100:создан
> 101:создан
> 100:оплачен
> 100:отгружен
> 101:оплачен
```

**Шаг 4. Покажите ключ, партицию и offset**

```bash
bin/kafka-console-consumer.sh --topic orders --from-beginning --bootstrap-server localhost:9092 \
  --formatter-property print.key=true --formatter-property print.partition=true \
  --formatter-property print.offset=true
```

Найдите события с ключом `100`: все они должны быть в одной партиции и идти в порядке `создан`, `оплачен`, `отгружен`. То же для ключа `101`.

**Шаг 5. Прочитайте одну партицию с выбранного места**

```bash
bin/kafka-console-consumer.sh --topic orders --partition 0 --offset 1 --max-messages 2 \
  --bootstrap-server localhost:9092
```

Этот консьюмер не использует группу, он сам указывает партицию и offset.

**Шаг 6. Наблюдайте за потоком в реальном времени**

В первом терминале запустите консьюмер из шага 4 (без `--from-beginning`), во втором — продюсер из шага 3. Каждое новое событие должно появляться в первом окне сразу после ввода.

### Что запомнить

| Ситуация | Что происходит |
| --- | --- |
| Ключ не задан | Партиция выбирается продюсером, порядок между партициями не гарантируется |
| Ключ задан | События с этим ключом идут в одну партицию, порядок внутри неё сохраняется |
| `--from-beginning` | Чтение начинается с самого раннего доступного события |
| Нет `--from-beginning` | Консьюмер получает только новые события |

### Контрольные вопросы

- Почему события с ключом `100` оказались в одной партиции?
- Что изменится в выводе, если запустить консьюмер без `--from-beginning`?
- Зачем у консьюмера может быть свойство `print.offset`?
- Что случится с событиями после чтения их консьюмером?

### Самостоятельное задание

Запишите 20 событий с ключами `A`, `B`, `C`. Составьте таблицу «ключ → партиция → список offset». Проверьте, что для каждого ключа все события лежат в одной партиции.
