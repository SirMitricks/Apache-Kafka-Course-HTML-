# Урок 3. Топики и партиции

**Цель:** создавать топики с нужным числом партиций, просматривать их устройство, менять настройки и удалять.

### Теория

Топик делится на **партиции**. Каждая партиция — это упорядоченный журнал, в конец которого дописываются события; у каждого события в партиции есть свой порядковый номер (offset). Партиции позволяют читать и писать параллельно на разных брокерах, поэтому число партиций задаёт верхнюю границу параллелизма (сколько читателей могут работать одновременно) у потребителей (подробнее в уроке 5).

Важные правила:

- Число партиций можно **увеличить**, но нельзя уменьшить.
- Порядок событий гарантируется только внутри одной партиции.
- При увеличении числа партиций события с одним ключом могут начать попадать в другую партицию, поэтому число партиций лучше выбирать с запасом заранее.

### Практика

Убедитесь, что брокер из урока 2 запущен, и работайте в новом терминале из каталога дистрибутива.

**Шаг 1. Создайте топик из трёх партиций**

```bash
bin/kafka-topics.sh --create --topic orders --partitions 3 --bootstrap-server localhost:9092
```

Ожидается сообщение `Created topic orders.` Фактор репликации (число копий каждой партиции) по умолчанию равен 1, потому что у нас один брокер.

**Шаг 2. Посмотрите список и описание**

```bash
bin/kafka-topics.sh --list --bootstrap-server localhost:9092
bin/kafka-topics.sh --describe --topic orders --bootstrap-server localhost:9092
```

В выводе найдите `PartitionCount: 3` и для каждой партиции поля `Leader` (брокер, ведущий партицию), `Replicas` (где лежат её копии) и `Isr` (какие копии актуальны). Сейчас везде будет один и тот же брокер; в уроке 6 здесь появятся несколько узлов.

**Шаг 3. Создайте топик с настройкой**

```bash
bin/kafka-topics.sh --create --topic logs --partitions 1 \
  --config retention.ms=3600000 --bootstrap-server localhost:9092
```

Здесь события хранятся один час (`retention` — срок хранения событий; `retention``.ms` задаётся в миллисекундах).

**Шаг 4. Увеличьте число партиций**

```bash
bin/kafka-topics.sh --alter --topic orders --partitions 6 --bootstrap-server localhost:9092
bin/kafka-topics.sh --describe --topic orders --bootstrap-server localhost:9092
```

Попробуйте затем указать `--partitions 2`. Kafka откажет: уменьшать число партиций нельзя. Запишите текст ошибки.

**Шаг 5. Удалите ненужный топик**

```bash
bin/kafka-topics.sh --delete --topic logs --bootstrap-server localhost:9092
```

### Как данные лежат на диске

Загляните в каталог из `log.dirs`: для каждой партиции есть папка вида `orders-0`, `orders-1` и так далее. Внутри лежат файлы сегментов (кусков журнала ограниченного размера) с расширениями `.log`, `.index`, `.timeindex`. Подробнее о сегментах в уроке 10.
