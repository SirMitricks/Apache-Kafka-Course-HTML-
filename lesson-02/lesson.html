Урок 2. Установка и первый запуск

Цель: запустить локальный брокер Kafka 4.3.1 в режиме KRaft и убедиться, что он отвечает.

Теория

Broker — это процесс (запущенная на компьютере программа) Kafka, который хранит данные и обслуживает клиентов. Раньше для хранения метаданных (служебной информации: какие есть топики и где лежат их копии) кластера (группы серверов Kafka, работающих как одно целое) требовался отдельный сервис ZooKeeper (отдельная программа-координатор, которую Kafka использовала раньше). В Kafka 4.x метаданными управляет сам Kafka по протоколу KRaft (встроенному в Kafka способу серверам договариваться, кто главный; протокол — набор правил общения программ): узел может быть брокером, контроллером (узлом, ведущим метаданные кластера) или совмещать обе роли. Для обучения мы запускаем один узел в совмещённой роли с файлом config/server.properties.

Перед первым запуском каталог данных нужно отформатировать (подготовить к хранению, как флешку перед записью) и присвоить кластеру уникальный идентификатор (Cluster UUID — случайная метка, по которой узлы узнают, что они из одного кластера).

Практика Б. Запуск в Docker (альтернатива)

Образ (готовый «слепок» программы со всём необходимым) apache/kafka уже содержит готовую одноузловую конфигурацию. Служебные скрипты лежат внутри контейнера (изолированной среды, в которой запущен образ): docker exec -it <имя_контейнера> bash, далее каталог /opt/kafka/bin.

Первое знакомство с каталогами

Каталог Содержимое
bin/ Скрипты: kafka-topics.sh, kafka-console-producer.sh и другие
config/ Файлы настроек: server.properties, connect-standalone.properties
libs/ Библиотеки Java, в том числе коннекторы
каталог логов Данные топиков; путь задаёт параметр log.dirs в server.properties

Частые ошибки

  • Unsupported class file major version: установлена Java ниже 17.
  • Порт 9092 занят: остановите другой процесс или поменяйте listeners в server.properties.
  • Брокер не стартует после смены каталога: повторите форматирование (kafka-storage.sh format) для нового log.dirs.

Самостоятельное задание

Откройте config/server.properties и найдите значения параметров process.roles, node.id, listeners и log.dirs. Запишите, что означает каждый, опираясь на раздел Configuration официальной документации.
